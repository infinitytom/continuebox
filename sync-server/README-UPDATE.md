# 续映服务端 0.27.1 / 客户端 2.2.1

本版增加“聚合全部”弹幕模式：合并弹弹play、danmu.zxz.ee、本地弹幕和应用已配置的弹幕接口。公共源只读，发送弹幕仍使用原服务。公共平台链接仅转发内容标识；其他播放地址在手机本地计算 MD5，不把带凭据的原始地址交给公共源。各源是否有弹幕取决于实际收录和匹配结果。

开放注册增加邮箱验证、持久化额度和访问限流。旧账号及其历史、收藏和第三方配置通过数据库增量迁移保留，无需重新注册。不要更换 TOKEN_SECRET：它同时参与登录令牌签名和第三方凭据加密。

## 更新

1. 备份当前 .env、应用代码和数据库。运行中的 SQLite 应通过备份 API 获取完整快照，或停止容器后备份整个 data 目录。
2. 将新版 app、Dockerfile、requirements.txt 更新到当前 Compose 构建目录。保留 .env、data、端口和原挂载位置。新版 docker-compose.yml 增加了 SMTP、管理员和可信代理环境变量；如使用旧 compose，也可以在 data/security.env 填写新增配置。
3. 配置现有管理员账号及邮箱 SMTP。QQ 邮箱使用 smtp.qq.com；支持 465/SSL 或 587/STARTTLS，本次已验证 587/STARTTLS，密码为邮箱 SMTP 授权码。不要使用 QQ 登录密码，不要把授权码写进 APK。
4. 如使用 data/security.env，权限必须设置为 600，目录不应公开分享。该文件只接受 SMTP_HOST、SMTP_PORT、SMTP_SECURITY、SMTP_USER、SMTP_PASSWORD、SMTP_FROM、ADMIN_USERNAMES，不会覆盖 TOKEN_SECRET 或其他第三方配置。
5. 运行 docker compose up -d --build。访问 /health 确认 0.27.1；/api/v1/auth/config 的 mail_ready 应为 true。
6. 新 APK 保留原签名，可以覆盖安装。旧账号可以继续用原用户名和密码登录；新注册需要至少 12 位密码及邮箱验证码。新客户端登录后，可在同步登录中的“账号与已登录设备”查看或解除登录。

已有容器的临时原位更新可运行部署包内的 deploy_in_container.py。脚本先验证更新文件摘要，再使用 SQLite 备份 API 创建快照并备份 /app/app，最后替换应用代码。随后重启同一个容器。**同时更新主机构建目录的 app 文件；否则重新创建容器会回到旧镜像。** 临时更新不修改原 .env 和端口。

## 默认保护额度

| 保护项 | 默认值 |
|---|---|
| 每日注册总量 / 每来源 IP 每日注册 | 20 / 3 |
| 每日验证邮件总量 / 每 IP / 每邮箱 | 100 / 10 / 5 |
| 验证码有效期 / 重发间隔 / 最大错误次数 | 10 分钟 / 60 秒 / 5 次 |
| 每 IP 和每账号 15 分钟登录次数 | 10 |
| 每 IP 每分钟请求 / 全站每分钟请求 | 300 / 2000 |
| 全站每分钟认证请求 | 60 |
| 每账号每分钟 / 每日弹幕发送 | 10 / 300 |
| 单个写入请求体 | 4 MiB |

每日额度按北京时间重置。计数器写入 SQLite，重启不会清空；注册额度与验证码消费在同一个写事务内完成，防止并发突破。限流使用固定窗口，在窗口边界可能产生短暂突发。邮件发送失败仍占用发送额度，避免通过失败重试绕过保护。

## 管理与设备

- /dashboard 提供管理员登录、账号列表、逐台设备解除、全部设备退出、安全额度设置、近期安全事件和本地弹幕管理。
- ADMIN_USERNAMES 必须填写你指定的**现有账号名**，逗号分隔；不能用尚未创建的名字授予权限。配置中的管理员名字无法通过开放注册创建。
- 管理 API 与统计接口要求管理员认证；页面本身不包含账号数据。管理令牌只在页面内存中保存，刷新需重新登录。
- 解除某台设备不会删除账号或历史。旧令牌无设备标识，逐台管理需要客户端升级后重新登录。退出所有设备也会撤销旧令牌。
- 用户注销账号 API 要求本人密码、已绑定邮箱的验证码和账号名确认；客户端主要入口提供设备解除，不把“退出登录”当成注销账号。
- 已下载的视频内容和已建立的播放连接无法通过退出登录收回；已签发的 Emby 临时播放地址最长仍可使用约一小时。同步和账户 API 的设备令牌撤销立即生效。

## 公网部署

公网入口使用有效 HTTPS 证书，后端 8080 不直接映射到公网。保留 ALLOW_REGISTER=true。未配置 SMTP 时，新注册会提示验证服务未配置，旧账号仍能登录；应完成邮件测试后再公开注册。

反向代理部署时只把代理实际来源 IP 加入 FORWARDED_ALLOW_IPS，禁止使用星号；确保客户端不能绕过代理直接访问后端。应用不直接信任用户提供的 X-Forwarded-For。

应用限流降低注册、邮件和密码猜测滥用；大流量攻击仍需要路由器、反向代理或上游网络的连接及带宽保护。请求日志不得记录密码、验证码、Authorization 或带签名的媒体 URL。

## 弹幕
